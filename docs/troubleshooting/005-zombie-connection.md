# 005. 네트워크 단절 시 WebSocket이 멈춘 채 복구 안 됨 (좀비 연결)

- 날짜: 2026-11-05
- 관련: [ADR 0009](../adr/0009-websocket-reconnect.md)

## 증상
Wi-Fi를 끄면 시세 수신이 멈추지만 `onClose`/`onError`가 호출되지 않는다. 재연결 로직이 이 콜백에만 의존하면 앱은 "연결 정상"으로 믿고 영원히 대기한다.

## 원인
TCP 연결은 상대가 사라진 것을 즉시 알지 못한다. 종료 신호(FIN)를 받지 못한 채 연결 객체는 살아 있는 상태로 남는다.

## 해결
마지막 수신 시각 기반 감지 추가. 10초마다 확인해 60초 이상 메시지가 없으면 `abort()` 후 재연결.

## 검증 (Wi-Fi 단절 테스트)
```
22:50:48  연결 성공 (Upbit, Binance)
          (Wi-Fi OFF — 콜백 호출 없음)
22:53:17  [binance] 64초간 수신 없음 → 강제 재연결
22:53:17  [upbit]   65초간 수신 없음 → 강제 재연결
22:53:19  연결 실패 ConnectException → 2.0~2.4초 후 재시도
22:53:21  연결 실패 → 4.7초 후 재시도
22:53:26  연결 실패 → 9.6초 후 재시도
22:53:35  연결 성공 (Wi-Fi ON 이후)
```
- 두 거래소의 재시도 간격이 조금씩 다름 → 지터 동작 확인
- Ctrl+C 종료 시 재연결 시도 없음 → `stopping` 플래그 동작 확인

## 남은 과제
- 감지 시간 단축 (클라이언트 ping/pong)
- 수신 공백(약 80초) 데이터 REST 보정

## 배운 점
"연결이 끊기면 콜백이 온다"는 가정은 틀릴 수 있다. 데이터가 실제로 들어오는지를 기준으로 판단해야 한다.
