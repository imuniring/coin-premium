# 0028. 환율 이력과 일자 전환 규칙

- 상태: 채택
- 날짜: 2026-11-27
- 관련: #81, ADR 0010, ADR 0027, 성능 003

## 맥락
- 공백 보정(ADR 0027)에는 "그 시각에 적용되던 환율"이 필요하다. Valkey에는 최신 환율 하나만 있다.
- 환율 이벤트의 `publishedAt`은 collector 규칙상 고시일 00:00 KST다. 그런데 수출입은행 API 안내는 "당행 환율 API에서 제공하는 데이터는 일환율 데이터로, 영업일 11시 전후로 업데이트"라고 한다.
- `publishedAt`을 그대로 적용 기준으로 쓰면 그날 0~11시 공백을 아직 고시되지 않은 환율로 계산하게 된다. 같은 오전 시간대의 LIVE(전날 환율)와 BACKFILL(당일 환율)이 달라지고, 김프가 1% 안팎이라 환율 차이(하루 0.1% 남짓)가 김프에서는 크다.

## 결정
1. premium이 이미 받는 환율 이벤트를 `fx_rate_history`(V3)에도 저장한다.
2. **서비스 공통 일자 전환 시각**: 고시일 D의 환율은 D 11:00 KST부터 적용한다 (`premium.fx.switch-time`, 설정값).

## 환율 이력
- 컬럼: `rate`, `published_at`(UNIQUE), `event_id`
- 기동 시 환율 토픽을 처음부터 다시 읽으므로, Kafka 보관 기간만큼 과거 이력이 자동으로 채워진다. UNIQUE로 중복은 무시된다.
- 리스너는 Valkey 반영(실시간)을 먼저 하고, 이력 저장은 따로 처리한다. DB 실패가 실시간 환율 반영을 막지 않고, 다음 기동 시 재소비로 다시 저장된다.
- 검토한 대안
  - 공백 직전 스냅샷의 환율 재사용: 공백 도중 환율이 바뀌면 틀리고, 직전 스냅샷이 없으면 불가
  - premium이 수출입은행 직접 호출: collector와 역할 중복, API 키 이중 관리

## 일자 전환 규칙
- `FxSwitchRule.publishedAtLimit(t)`: t(KST)가 전환 시각 전이면 전날, 이후면 당일의 00:00 KST를 상한으로 돌려준다. 저장소는 상한 이하에서 가장 최근 환율만 찾는다 (규칙은 도메인, 조회는 단순하게).
- 주말·공휴일은 고시가 없어 자연히 직전 영업일 환율이 된다.
- 날짜는 한국 기준으로 판단한다 (UTC로는 전날인 KST 새벽 주의).
- 검토한 대안: Kafka 메시지 시각(실제 수신 시각) 기준. "그때 실제로 쓴 환율"을 재현하지만 우리 수집 지연에 따라 결과가 달라진다. 이력은 규칙으로 정해지는 편이 대사·통계에 적합하다.

## 검증
11/27 보정 결과에서 정확히 11:00 KST에 환율이 바뀌었다 (성능 003).

| captured_at (UTC) | KST | exchange_rate |
| --- | --- | --- |
| 01:59 | 10:59 | 1343.9 (11/26 고시) |
| 02:00 | 11:00 | 1342.7 (11/27 고시) |

## 트레이드오프
- 11:00 ~ collector의 실제 수신(30분 주기, 최대 약 30분) 사이에는 LIVE는 전날, BACKFILL은 당일 환율이다. BACKFILL 쪽이 공식 기준에 맞는 값이다. 필요하면 11시 전후 조회 주기를 줄인다.
- 규칙은 collector의 `publishedAt` = 고시일 00:00 KST 약속에 기댄다. 그 약속이 바뀌면 함께 바꿔야 한다.
- "11시 전후"라 정확한 시각이 아닐 수 있다. collector가 새 환율을 처음 받는 시각을 모아 설정값을 조정한다.
