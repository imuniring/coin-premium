# 0007. Kafka 도입, 메시지 키 = 심볼

- 상태: 채택
- 날짜: 2026-11-05

## 맥락
collector와 premium-service를 직접 호출로 연결하면, premium이 느려지거나 꺼질 때 collector도 같이 영향을 받고 시세가 유실된다. 이후 market-service, 알림 등 같은 시세를 쓰는 소비자가 늘어난다.

## 결정
- 서비스 간 통신은 Kafka 비동기
- 토픽: `market.ticker.v1` (파티션 3), `market.exchange-rate.v1` (파티션 1)
- 시세 메시지 키 = 심볼 (`BTC`), 환율 키 = `USD-KRW`
- producer: `acks=all`, `enable.idempotence=true`, `linger.ms=5`, JSON 타입 헤더 비활성화
- 토픽 이름은 contract 모듈 `Topics` 상수로 공유

## 이유
- 장애 격리·독립 확장·독립 배포를 실제로 가능하게 함
- 소비자가 늘어도 collector는 변경 없음
- 키를 심볼로 하면 같은 코인의 국내·해외 시세가 같은 파티션에 모여, premium-service를 여러 대로 늘려도 한 인스턴스가 김프를 계산할 수 있음
- 토픽에 `.v1`을 붙여 호환되지 않는 변경 시 새 토픽으로 분리 가능

## 선택지 비교 (키)
| 키 | 결과 |
| --- | --- |
| 없음 | 순서 보장 없음 |
| 거래소+심볼 | 국내·해외 BTC가 다른 파티션으로 갈 수 있음 |
| 심볼 | 같은 코인끼리 같은 파티션 (채택) |

## 트레이드오프
- 거래량이 많은 코인에 핫 파티션 발생 가능 → 코인 수가 늘면 파티션 분포 모니터링
- 시세는 비동기 전송이라 전송 실패 시 해당 체결은 유실 (로그에 eventId 기록). 다음 체결이 곧 덮으므로 1단계에서는 허용, 3단계 Outbox에서 재검토
