# 0010. 환율 수집 전략

- 상태: 채택
- 날짜: 2026-11-06

## 맥락
김프 계산에 USD→KRW 환율이 필요하다. 수출입은행 환율은 영업일 하루 1회 고시되고, 주말·공휴일·고시 전에는 빈 배열을 반환한다.

## 결정
- 출처: 한국수출입은행 환율 API, 매매기준율(`deal_bas_r`)
- 실행: 기동 5초 후 1회 + `fixedDelay` 30분
- 오늘부터 최대 7일 전까지 거꾸로 조회 (주말·긴 연휴 대응)
- 실패 분류
  - 일시적(IOException, 타임아웃, 5xx): 최대 3회 재시도 (1s → 2s)
  - 영구(인증 오류·일일 제한 등 result≠1, 4xx, USD 없음): 재시도 안 함
- 직전 발행과 같은 eventId면 생략. 발행 성공 후에만 기록
- Kafka 동기 전송 (5초 타임아웃)
- 수집 규칙은 `ExchangeRateCollector` 서비스, 시간은 `Clock`(KST) 주입

## 이유
- 하루 1회만 조회하면 고시 지연·호출 실패·재시작 시 하루 종일 환율이 없을 수 있음
- 영구 실패를 재시도하면 일일 호출 한도만 소모
- `fixedRate`는 재시도로 실행이 길어지면 겹칠 수 있고, `cron`은 기동 직후 실행이 안 됨
- 환율은 건수가 적고 1건 유실 시 30분 공백이 생겨 동기 전송으로 성공 여부를 확인 (시세는 비동기 유지)
- Clock 주입으로 "토요일인 척" 테스트 가능

## 검증
- 단위 테스트: 주말 거꾸로 조회, 일시적 실패 재시도, 영구 실패 미재시도, 중복 발행 생략
- 실제: 11/6(KST) 00:11, 고시 전 시점에 11/5 환율로 거꾸로 조회되어 발행

## 트레이드오프 / 다음 과제
- 직접 구현한 재시도 → 2단계 Resilience4j(Retry, CircuitBreaker)로 교체
- 다중 인스턴스 시 중복 실행 → 분산 락(ShedLock)
- USDT를 USD와 같다고 보는 근사 → 테더 기준 김프(Upbit USDT/KRW)를 RateSource로 추가 검토
