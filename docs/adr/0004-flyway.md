# 0004. 스키마 관리로 Flyway 선택

- 상태: 채택 (premium-service에서 도입 예정)
- 날짜: 2026-11-05

## 맥락
스키마 변경 이력을 코드로 관리하고, jOOQ 코드 생성의 원천으로 쓰고 싶다.

## 선택지
- A: Flyway (버전별 SQL 파일을 순서대로 적용)
- B: Atlas (원하는 최종 스키마를 선언, 차이를 계산)

## 결정
A. Flyway를 사용하고, Atlas는 마이그레이션 lint 용도로 CI에서 선택적으로 검토한다.

## 이유
- Spring Boot 자동 지원, 자료가 많음
- "Testcontainers로 MariaDB 기동 → Flyway 적용 → jOOQ 코드 생성" 파이프라인으로 SQL 파일 하나가 스키마와 코드의 단일 원천이 됨
- 빌드 시 로컬 DB가 필요 없음

## 트레이드오프
- 위험한 변경(컬럼 삭제, 긴 락) 자동 감지가 없음 → Atlas lint로 보완 검토
- 두 도구를 모두 "적용"에 쓰면 충돌하므로 Atlas는 검사 용도로만
