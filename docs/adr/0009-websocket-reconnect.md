# 0009. WebSocket 재연결·좀비 연결 감지

- 상태: 채택
- 날짜: 2026-11-05

## 맥락
- Binance는 연결 하나를 24시간만 유지하고 강제로 끊는다
- 네트워크 단절 시 `onClose`/`onError`가 호출되지 않아 연결이 살아있는 척 멈추는 좀비 상태가 실제로 발생했다 ([트러블슈팅 005](../troubleshooting/005-zombie-connection.md))
- Upbit·Binance 수신 코드에 중복이 많았다

## 결정
- 공통 부모 `ExchangeWebSocketClient` (템플릿 메서드 패턴). 자식은 이름·주소·구독 메시지·메시지 변환만 구현
- 재연결 트리거: 연결 종료, 에러, 연결 실패, 60초 무수신
- 지수 백오프 1s → 2s → 4s … 최대 60s, 0~20% 지터
- 백오프 초기화는 연결 성공이 아니라 첫 메시지 수신 시점
- `AtomicBoolean`으로 재연결 중복 예약 방지, `stopping` 플래그로 종료 중 재연결 차단
- 연결마다 새 Listener 생성 → 끊기기 전 버퍼 조각이 새 연결에 섞이지 않음
- 메시지 1건 처리 실패는 로그 후 버리고 연결 유지

## 이유
- 백오프: 거래소 점검 중 무한 재시도로 IP 차단되는 것 방지
- 지터: 여러 연결이 동시에 끊겼을 때 같은 타이밍에 몰리는 것 방지
- 첫 메시지 기준 초기화: 연결 직후 끊김이 반복될 때 1초 간격 무한 재시도 방지

## 검증 결과 (Wi-Fi 단절 테스트)
- 단절 후 onClose/onError 미호출 → 약 65초 후 좀비 감지
- 단절 중 재연결 간격 1.09s → 2.04s → 4.70s → 9.59s
- 네트워크 복구 후 Upbit·Binance 자동 재연결, 수신 공백 약 80초
