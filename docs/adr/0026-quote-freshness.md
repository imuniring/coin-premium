# 0026. 시세 신선도: 저장은 엄격하게, 보여 주기는 솔직하게

- 상태: 채택
- 날짜: 2026-11-27
- 관련: #75, ADR 0022, ADR 0027, 성능 003

## 맥락
- 최신 시세를 Valkey에 영속화(ADR 0021·0022)한 뒤, collector가 멈춰도 premium은 남은 시세를 "준비됨"으로 판단했다.
- collector 중단 상태에서 BTC 김프가 30분간 `1.0596`으로 고정된 채 LIVE 스냅샷으로 저장됐다. Valkey의 마지막 Upbit 체결은 10:25:46 KST였고, 13~43분 지난 시세로 계산한 값이었다 (성능 003).
- 메모리 저장소 시절에는 재시작하면 시세가 비어 503이 났지만, 영속화로 "오래된 값"이라는 새 문제가 생겼다.
- 빈 줄보다 오래된 값으로 채운 줄이 더 위험하다. 줄이 다 있어 공백으로 보이지 않고, 틀린 값이 진짜처럼 남는다.

## 결정
- 국내·해외 시세의 체결 시각이 60초보다 오래되면 stale로 판단한다 (`premium.freshness.max-quote-age: 60s`).
- **스냅샷 저장(이력)**: stale이면 저장하지 않는다. 공백이 되어 보정 대상이 된다 (ADR 0027).
- **실시간 조회 API**: 값을 주되 `stale: true`로 표시한다 (200). 시세가 아예 없을 때만 503 `MARKET_DATA_NOT_READY`.
- 환율은 대상이 아니다. 영업일 1회 고시라 주말엔 며칠 지난 값이 정상이다 (영업일 기준 지연 감시는 5단계).

## 이유
- 이력은 차트·통계·대사의 기준 데이터라 한 번 틀린 값이 들어가면 계속 남는다. 저장은 엄격해야 한다.
- 실시간 조회의 주 사용처는 대시보드다. 503을 주면 리더 교대 같은 짧은 지연에도 화면이 깨지거나 깜빡인다. 마지막 값과 함께 "오래됨"을 알려 주면 화면은 유지하면서 사용자가 지연을 알 수 있다 (`tradedAt`으로 경과 시간 표시).
- 60초: collector 리더 교대(15~20초)로는 걸리지 않고, 실제 장애는 1분 안에 감지된다.
- "값 없음"(503)과 "값이 오래됨"(200 + stale)을 구분한다.

## 구성
- `PriceQuote.isStale(now, maxAge)`: 체결 시각이 `now - maxAge`보다 이전이면 stale (정확히 60초는 신선)
- 계산 시각과 판단 기준 시각은 같은 `now`를 쓴다.
- `PremiumSnapshot.stale`, `PremiumResponse.stale` (기본값 없이 생성 시 반드시 지정)

## 트레이드오프
- 대시보드 쪽에서 `stale`을 반드시 처리해야 오래된 값이 정상처럼 보이지 않는다.
- 다시 볼 조건: 거래가 뜸한 코인을 추가해 체결 없는 60초가 흔해지면, 공백이 자주 생기고 거래소 분봉에도 빈 분이 있어 보정도 어렵다. 코인별 기준이나 다른 신선도 정의를 검토한다.
