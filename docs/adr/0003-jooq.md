# 0003. 쿼리 도구로 jOOQ 선택

- 상태: 채택 (premium-service에서 도입 예정)
- 날짜: 2026-11-05

## 맥락
캔들 집계·통계처럼 SQL 중심 조회가 많다. 기존 실무는 MyBatis(XML)를 써서 오타·컬럼명 변경을 실행 시점에야 발견했다.

## 선택지
- A: MyBatis (XML)
- B: JPA + QueryDSL
- C: Spring JdbcClient
- D: jOOQ

## 결정
D. 핵심 조회는 jOOQ로 작성한다. 단순 쿼리나 jOOQ가 지원하지 않는 DB(QuestDB 등)는 JdbcClient를 사용한다.

## 이유
- 스키마 기반 코드 생성으로 컬럼명·타입 오류를 컴파일 시점에 발견
- 스키마 변경 시 영향 범위를 컴파일러가 알려줌
- 동적 조건을 `DSL.noCondition()`으로 깔끔하게 조립
- 집계·윈도우 함수 등 SQL 표현력이 높음

## 트레이드오프
- 코드 생성 단계가 빌드에 추가된다 → Flyway + Testcontainers 파이프라인으로 해결 (0004)
- 복잡한 SQL을 DSL로 옮겨 적어야 한다
- Open Source Edition의 지원 DB·Java 버전 조건은 도입 시 재확인 필요
