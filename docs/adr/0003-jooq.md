# 0003. 쿼리 도구로 jOOQ 선택

- 상태: 채택 (2026-11-11 코드 생성 방식 갱신)
- 날짜: 2026-11-05

## 맥락
캔들 집계·통계처럼 SQL 중심 조회가 많다. 기존 실무는 MyBatis(XML)를 써서 오타·컬럼명 변경을 실행 시점에야 발견했다.

## 선택지
- A: MyBatis (XML)
- B: JPA + QueryDSL
- C: Spring JdbcClient
- D: jOOQ

## 결정
D. 핵심 조회·저장은 jOOQ로 작성한다. 단순 쿼리나 jOOQ가 지원하지 않는 DB(QuestDB 등)는 JdbcClient를 사용한다.

### 코드 생성 방식 (갱신)
- 처음 계획: Testcontainers로 MariaDB를 띄우고 Flyway 적용 후 그 DB에서 코드 생성
- 변경: jOOQ `DDLDatabase`로 **Flyway SQL 파일을 직접 파싱**해 코드 생성
  - 공식 플러그인 `org.jooq.jooq-codegen-gradle` + `jooq-meta-extensions`
  - `scripts = src/main/resources/db/migration/*.sql`, `sort = flyway`, `defaultNameCase = lower`
  - 플러그인 버전은 Spring Boot 4.1.2가 관리하는 jOOQ 버전(3.21.9)과 일치시킨다 (`dependencyInsight`로 확인)

## 이유
- 스키마 기반 코드 생성으로 컬럼명·타입 오류를 컴파일 시점에 발견
- 스키마 변경 시 영향 범위를 컴파일러가 알려줌
- 동적 조건을 `DSL.noCondition()`으로 조립, 집계·윈도우 함수 등 SQL 표현력이 높음
- DDLDatabase는 빌드 시 DB·Docker가 필요 없어 로컬·CI 빌드가 단순하다 (Open Source Edition 지원)
- `defaultNameCase = lower`: Linux MariaDB는 테이블명 대소문자를 구분하므로 소문자 유지

## 트레이드오프
- DDLDatabase는 SQL을 H2 기반으로 해석하므로 MariaDB 전용 문법을 많이 쓰면 파싱이 실패할 수 있다 → 마이그레이션 SQL은 표준에 가깝게 작성
- Spring Boot 업그레이드로 jOOQ 버전이 바뀌면 카탈로그의 `jooq` 버전도 함께 맞춰야 한다
- 생성 코드는 `build/`에 있어 Git에 올리지 않고 빌드마다 재생성
- 생성 테이블 클래스(`PremiumSnapshot`)와 애플리케이션 record 이름이 겹칠 수 있음 → 생성 코드는 `Tables` 상수만 static import ([트러블슈팅 009](../troubleshooting/009-class-name-collision.md))
